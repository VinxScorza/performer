Important project compatibility warning

The 0.4.6 beta can open projects saved by 0.4.4 and 0.4.5, but saving them upgrades the file to Version41. Firmware 0.4.5 and earlier cannot reopen that upgraded file. Back up the SD card or keep a separate copy of every project before opening and saving it with the beta.

PER|FORMER is a eurorack sequencer module designed for both live performance and work in the studio.
This firmware is a personal fork of the Mebitek fork of the original Westlicht PER|FORMER firmware, and is shaped by real performance use, custom behavior, and focused interaction and UI changes.

Major Features

This fork remains intentionally personal, exploratory, and performance-driven.
What I'm aiming for is a solid machine for live performance, but also a crazy one for experimenting.
The goal is not simply to add more options, but to push PER|FORMER toward stronger creative generators, safer destructive workflows, better live interaction, and a more complete simulator and documentation ecosystem.

Historical baseline: Mebitek and original Westlicht lineage.

Generators & Performance Workflow

  • Random, Euclidean, Acid, and Chaos now form a broader generator ecosystem built around preview/apply safety, A/B comparison, and live-performance use.
  • Acid includes Layer, Phrase, and Eucl Phrase; Chaos expands into Vandalize, Wreck, and non-Note Entropy.
  • Launchpad Generators Mode, Init actions, Undo/Redo, and safer cancel/apply behavior make the generator workflow playable from both the module and external controllers.

Step Editing, Timing & Sequencing

  • External 16-step Editing Mode adds direct note/gate editing for Note tracks with 16-knob + 16-pad controllers.
  • Core sequencing gained bank-aware range editing, chain-aware note ties, improved step selection, Curve gate timing layers, and per-track Gate/Trigger output behavior.
  • Clock/reset behavior, scale handling, Voltage Mode paths, and Arp/Stochastic scale-safe transpose were tightened for more predictable performance use.
  • In the 0.4.6 beta, selected-step Copy/Paste/Duplicate is safer across Note, Curve, Stochastic, Logic, and Arp, and double-clicking a track button provides direct access to its Steps editor where available.
  • Held Fill controls can temporarily change a track's playback divisor from the module encoder, including fills initiated from Launchpad, without replacing the divisor stored in the sequence.

Memory, Runtime & Build Robustness

  • Reduced STM32 memory pressure and improved runtime efficiency, with additional hardening around the heaviest generator paths.
  • Build and simulator paths were cleaned up and aligned with current firmware behavior. The Vagrant setup now stops on errors, verifies the CMake download checksum, and installs the required CMake and Python tooling.

Core Engine & Safety

  • Generator and modal UI paths were hardened against wrong-target apply/cancel behavior, stale state, and controller retargeting edge cases.
  • Routing/CV control now treats continuous, discrete, and trigger-like targets more safely and filters writes by compatible track mode.
  • Load, Save, Save As, project browsing, and slower SD-card boot paths were hardened to reduce race and reboot-prone behavior.
  • The 0.4.6 beta adds per-project filters for MIDI Notes, CC, Program Change, Pitch Bend, and Aftertouch. Their state is stored in project format Version41; custom Program Change mapping is not included.
  • Routing Divisor Min/Max now follows valid musical divisions, while Stochastic and the related Arp pitch path preserve scale-note interpretation across project reloads.

Docs, Site & Ecosystem

  • The site now separates roles clearly: Home for overview, Features for the curated feature map, User Manual for practical use, Build Guide for hardware/build/simulator setup, and Cheatsheet for Launchpad reference.
  • The online manual includes search/navigation and a printable manual PDF.
  • The Web Simulator now runs the 0.4.6 beta firmware, with its beta status shown separately from the stable v0.4.5 download.

And much more across the wider firmware line.
For the broader curated overview, see FEATURES. For the exact technical chronology, including inherited upstream history, see the repository CHANGELOG.

Known Limits / Validation Scope

Current real-hardware validation snapshot. Full scope and detailed notes are maintained in the User Manual validation section.

  • Beta validation The v0.4.6-beta.1 firmware and simulators build successfully; the focused real-hardware upgrade smoke test remains to be completed.
  • Validated 16-step Editing Mode maintainer-side hardware validation is on Launch Control XL (Factory Preset #1).
  • Pending hardware test BeatStep Pro template/mapping is code-supported but still needs dedicated maintainer-side on-device validation.
  • Partially validated Voltage Mode is fixed across Note/Arp/Stochastic; uncommon notesPerOctave > 12 cases on Arp/Stochastic still benefit from broader field tests.
  • Partially validated Desktop Simulator USB MIDI is currently validated on macOS / OS X with Launchpad Mini MK3, not yet across all devices/OS combinations.
  • Known architecture limit One external USB controller workflow at a time; USB hubs (including powered hubs) are not supported by the current firmware USB host stack.
  • Stability hardening Save/Save As/Load race conditions were strongly mitigated, but full architectural closure is still in progress.
